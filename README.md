## Основные инженерные решения

1. **Разделение контуров безопасности:**  
   Аппаратная часть трости (датчики, дешифратор, индикация) и мобильное приложение функционируют независимо. В случае сбоя или разрядки телефона система индикации поворотов продолжает штатно работать.
2. **Фильтрация шума походки (Гистерезис + Hold-Time):**  
   Естественные маятниковые колебания трости при ходьбе отсекаются программным фильтром: порог наклона $25^\circ$, зона гистерезиса $8^\circ$ (возврат при $<17^\circ$) и тайм-аут удержания $250\text{ мс}$. Это исключает ложные вспышки светодиодов при обычном шаге.
3. **Аппаратная взаимоблокировка (74HC138):**  
   Управление светодиодами перенесено на 3-to-8 дешифратор КМОП-серии 74HC138. Включение двух светодиодов одновременно невозможно на физическом уровне микросхемы.
4. **Тактильный отклик и беспроводная связь:**  
   Bluetooth-модуль HC-05 принимает команды от приложения компьютерного зрения (детектор препятствий) и запускает короткий импульс вибромотора через транзисторный ключ.

## Архитектура системы

Система разделена на три функциональные аппаратные подсистемы трости и внешний мобильный контур:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      МОБИЛЬНЫЙ КОНТУР (Android App)                    │
│   Камера смартфона ──► Детекция препятствий (ML Kit) ──► Bluetooth TX │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Bluetooth (SPP)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        АППАРАТНАЯ ЧАСТЬ ТРОСТИ                         │
│                                                                        │
│  [1. ПОДСИСТЕМА НАПРАВЛЕНИЯ]                                           │
│  MPU6050 (IMU) ──I2C──► Arduino Nano ──D2..D4──► 74HC138 ──► Светодиоды│
│                                                                        │
│  [2. РЕЗЕРВНАЯ ПОДСИСТЕМА ДИСТАНЦИИ]                                   │
│  HC-SR04 (ультразвук) ──Trig/Echo──► Arduino Nano (контроль дистанции) │
│                                                                        │
│  [3. ПОДСИСТЕМА СВЯЗИ И ТАКТИЛЬНОГО ОТКЛИКА]                           │
│  HC-05 (BT) ──D10/D11──► Arduino Nano ──D9 (PWM)──► NPN ──► Вибромотор │
│                                                                        │
│  [ПИТАНИЕ]: 18650 Li-Ion (3.7V) ──► Battery Shield (Boost 5V) ──► +5V  │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Подсистема классификации направления:** Датчик MPU6050 измеряет угол крена трости, микроконтроллер фильтрует шум ходьбы и выставляет двоичный код на входы КМОП-дешифратора 74HC138, переключающего светодиоды поворота.
2. **Резервная подсистема ультразвука:** Датчик HC-SR04 обеспечивает автономное измерение расстояния до препятствий непосредственно перед пользователем.
3. **Подсистема связи и виброотклика:** Модуль HC-05 по интерфейсу UART принимает команду `VIBRATE`, микроконтроллер формирует ШИМ-импульс через транзисторный драйвер на вибромоторчик в ручке.

## Сборка и прошивка

### Необходимые библиотеки Arduino:
- `Wire` (входит в стандартную поставку Arduino AVR)
- `SoftwareSerial` (входит в стандартную поставку Arduino AVR)
- `MPU6050_light` (устанавливается через Library Manager в Arduino IDE)

### Прошивка:
1. Подключите Arduino Nano к ПК через USB.
2. Откройте [firmware/argus_cane/argus_cane.ino](firmware/argus_cane/argus_cane.ino) в Arduino IDE.
3. Выберите плату **Arduino Nano**, процессор **ATmega328P** (или *Old Bootloader*) и нужный COM-порт.
4. Загрузите скетч.
5. При подаче питания трость должна стоять неподвижно и вертикально в течение 2–3 секунд для калибровки MPU6050.

## Тестирование

Логика классификации вынесена в отдельный платформонезависимый C++ класс и тестируется локально без подключенного железа:

### Сборка и запуск тестов:

**GCC / Clang:**
```bash
cd firmware/direction_logic
g++ -std=c++11 test_direction_logic.cpp direction_logic.cpp -o test_runner
./test_runner
```

**MSVC (Developer Command Prompt):**
```cmd
cd firmware\direction_logic
cl /EHsc /std:c++17 test_direction_logic.cpp direction_logic.cpp /Fe:test_runner.exe
test_runner.exe
```

Сценарии проверяют:
- Нейтральный угол ($0^\circ$) -> `CENTER`;
- Кратковременные всплески наклона ($<250\text{ мс}$) -> фильтрация шума шага;
- Устойчивый наклон ($>25^\circ, >250\text{ мс}$) -> переход в `RIGHT` / `LEFT`;
- Корректность зоны гистерезиса при возврате в `CENTER` (возврат строго при угле $<17^\circ$).
