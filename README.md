## Основные инженерные решения

1. **Разделение контуров безопасности:**  
   Аппаратная часть трости (датчики, дешифратор, индикация, тактильный отклик) и мобильное приложение функционируют независимо. В случае сбоя, зависания или разрядки смартфона все жизненно важные ассистивные функции трости продолжают штатно работать.
2. **Фильтрация шума походки (Гистерезис + Hold-Time):**  
   Естественные маятниковые колебания трости при ходьбе отсекаются программным фильтром: порог наклона $25^\circ$, зона гистерезиса $8^\circ$ (возврат при $<17^\circ$) и тайм-аут удержания $250\text{ мс}$. Это исключает ложные вспышки светодиодов при обычном шаге.
3. **Аппаратная взаимоблокировка (74HC138):**  
   Управление светодиодами перенесено на 3-to-8 дешифратор КМОП-серии 74HC138. Включение двух светодиодов одновременно невозможно на физическом уровне микросхемы.
4. **Автономный тактильный отклик и односторонняя телеметрия:**  
   Локальный ультразвуковой датчик (RCWL-9610A / HC-SR04) автономно управляет вибромоторчиком через транзисторный ключ (логика прототипа P0002). Модуль Bluetooth HC-05 используется исключительно для односторонней передачи данных телеметрии (дистанция и направление) на смартфон, исключая зависимость трости от внешних входящих команд.

## Архитектура системы

Система разделена на три функциональные аппаратные подсистемы трости и внешний мобильный контур:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      МОБИЛЬНЫЙ КОНТУР (Android App)                    │
│   Прием телеметрии (SPP) ──► Отображение статуса, навигация, голос     │
└───────────────────────────────────▲────────────────────────────────────┘
                                    │ Bluetooth (SPP) — ТОЛЬКО ИСХОДЯЩИЙ ПОТОК
                                    │ Telemetry: "DIST:<см>,DIR:<DIR>\n"
┌───────────────────────────────────┴────────────────────────────────────┐
│                        АППАРАТНАЯ ЧАСТЬ ТРОСТИ                         │
│                                                                        │
│  [1. ПОДСИСТЕМА НАПРАВЛЕНИЯ]                                           │
│  MPU6050 (IMU) ──I2C──► Arduino Nano ──D2..D4──► 74HC138 ──► Светодиоды│
│                                                                        │
│  [2. ПОДСИСТЕМА ДИСТАНЦИИ И ТАКТИЛЬНОГО ОТКЛИКА] (Прототип P0002)      │
│  RCWL-9610A ──D5/D6──► Arduino Nano ──D9 (PWM)──► NPN ──► Вибромотор   │
│                                                                        │
│  [3. ПОДСИСТЕМА ТЕЛЕМЕТРИИ]                                            │
│  Arduino Nano (D11 TX) ──[1k/2k]──► HC-05 (BT TXD)                     │
│                                                                        │
│  [ПИТАНИЕ]: 18650 Li-Ion (3.7V) ──► Battery Shield (Boost 5V) ──► +5V  │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Подсистема классификации направления:** Датчик MPU6050 измеряет угол крена трости, микроконтроллер фильтрует шум ходьбы и выставляет двоичный код на входы КМОП-дешифратора 74HC138, переключающего светодиоды поворота.
2. **Подсистема дистанции и тактильного отклика:** Ультразвуковой сенсор RCWL-9610A (HC-SR04) автономно контролирует зону перед пользователем. При приближении к препятствию ближе 50 см микроконтроллер активирует вибромотор через транзисторный ключ на пине D9 (PWM).
3. **Подсистема исходящей телеметрии:** При фиксации препятствия Arduino формирует строку `DIST:<см>,DIR:<CENTER|LEFT|RIGHT>\n` и передает её в Bluetooth-модуль HC-05 (TX на пине D11) для информирования смартфона.

## Архитектурное решение: односторонняя телеметрия

Главный архитектурный принцип Argus — **полная независимость контуров безопасности**:

- **Односторонний поток (трость ──► телефон):** Bluetooth используется исключительно как транспорт для исходящих данных (телеметрия расстояния и текущего классифицированного направления).
- **Отсутствие внешнего управления:** Трость не слушает эфир и не содержит логики, которая ожидает входящие команды с телефона для включения вибромотора или светодиодов.
- **Гарантированная безопасность:** Даже при разряженном смартфоне, сбое в мобильном приложении или потере Bluetooth-соединения пользователь сохраняет 100% критического функционала: трость продолжает самостоятельно индицировать повороты светодиодами и тактильно предупреждать о препятствиях вибромотором.

## Сборка и прошивка

### Необходимые библиотеки Arduino:
- `Wire` (входит в стандартную поставку Arduino AVR)
- `SoftwareSerial` (входит в стандартную поставку Arduino AVR)
- `MPU6050_light` (устанавливается через Library Manager в Arduino IDE)

### Прошивка:
1. Подключите Arduino Nano к ПК через USB.
2. Откройте [firmware/argus_cane/argus_cane.ino](firmware/argus_cane/argus_cane.ino) в Arduino IDE.
3. Выберите плату **Arduino Nano**, процессор **ATmega328P** (или *Old Bootloader*) и нужный COM-порт.
4. Загрузите скетч.
5. При подаче питания трость должна стоять неподвижно и вертикально в течение 2–3 секунд для калибровки MPU6050.

## Тестирование

Логика классификации вынесена в отдельный платформонезависимый C++ класс и тестируется локально без подключенного железа:

### Сборка и запуск тестов:

**GCC / Clang:**
```bash
cd firmware/direction_logic
g++ -std=c++11 test_direction_logic.cpp direction_logic.cpp -o test_runner
./test_runner
```

**MSVC (Developer Command Prompt):**
```cmd
cd firmware\direction_logic
cl /EHsc /std:c++17 test_direction_logic.cpp direction_logic.cpp /Fe:test_runner.exe
test_runner.exe
```

Сценарии проверяют:
- Нейтральный угол ($0^\circ$) -> `CENTER`;
- Кратковременные всплески наклона ($<250\text{ мс}$) -> фильтрация шума шага;
- Устойчивый наклон ($>25^\circ, >250\text{ мс}$) -> переход в `RIGHT` / `LEFT`;
- Корректность зоны гистерезиса при возврате в `CENTER` (возврат строго при угле $<17^\circ$).
