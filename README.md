## Key Engineering Highlights

1. **Два независимых контура с полной изоляцией отказа (Fault Isolation):**  
   Аппаратный контур трости (IMU + Arduino + 74LS138) и мобильный контур (смартфон с камерой и ИИ) работают автономно без общих шин данных или синхронных блокировок. Сбой или разрядка телефона не нарушает работу индикации поворотов на трости, и наоборот.
2. **Фильтрация шума походки (Hysteresis + Hold-Time):**  
   Маятниковые колебания трости при каждом шаге человека отсекаются двухступенчатым программным фильтром: порог наклона $25^\circ$, зона нечувствительности $8^\circ$ (возврат при $<17^\circ$) и тайм-аут удержания $250\text{ мс}$. Это предотвращает ложные кратковременные срабатывания светодиодов во время нормальной ходьбы.
3. **Аппаратная комбинационная логика (74LS138):**  
   Принятие решения о включении конкретного индикатора перенесено на интегральный дешифратор 3-to-8. Микроконтроллер передает только бинарный код направления, а физическая взаимоблокировка (включение только одного выхода в момент времени) гарантируется на уровне кремниевой логики ТТЛ, исключая конфликтные состояния сигналов в соответствии с каноническими принципами архитектуры ЭВМ.

## Tech Stack

| Подсистема | Технологии и компоненты | Назначение |
|:---|:---|:---|
| **Cane Hardware** | Arduino Nano (ATmega328P), 74LS138 IC | Вычислительный микроконтроллер и аппаратный ТТЛ-дешифратор |
| **Sensors** | MPU6050 (GY-521) | 6-осевой гироскоп и акселерометр по шине I2C |
| **Firmware Core** | Pure C++11/C++17 | Чистая логика классификации поворотов без внешних библиотек |
| **Arduino Stack** | Arduino C++, Wire, `MPU6050_light` | Опрос шины I2C, калибровка смещений и вывод на GPIO |
| **Mobile App (Future)** | Kotlin, Jetpack Compose, CameraX, ML Kit | Мобильное приложение распознавания препятствий (папка `mobile-app`, в планах) |

## Getting Started

### Необходимое оборудование и ПО:
1. **Плата:** Arduino Nano (ATmega328P).
2. **Датчик:** MPU6050 (подключен к пинам A4/SDA и A5/SCL).
3. **Микросхема логики:** 74LS138 (входы A, B, C подключены к D2, D3, D4; выходы Y1, Y2 — к светодиодам через резисторы 330 Ом). Подробная схема: [docs/pinout.md](docs/pinout.md).
4. **Среда разработки:** Arduino IDE 1.8.x, Arduino IDE 2.x или `arduino-cli`.
5. **Библиотеки Arduino:**
   - `Wire` (встроена в ядро Arduino AVR)
   - `MPU6050_light` (автор: *rfetick*) — устанавливается через *Library Manager* (Скетч -> Подключить библиотеку -> Управлять библиотеками).

### Прошивка микроконтроллера:
1. Подключите Arduino Nano к компьютеру через USB-кабель.
2. В Arduino IDE откройте файл [firmware/argus_cane/argus_cane.ino](firmware/argus_cane/argus_cane.ino).
3. В меню **Инструменты (Tools)** выберите:
   - **Плата:** *Arduino Nano*
   - **Процессор:** *ATmega328P* (или *ATmega328P (Old Bootloader)* для большинства плат CH340)
   - **Порт:** соответствующий COM-порт устройства.
4. Нажмите кнопку **Загрузка (Upload)**.
5. **Важно при включении:** Во время калибровки смещений (`mpu.calcOffsets()`, первые 2-3 секунды после включения) трость должна быть **неподвижна и находиться в строго вертикальном нейтральном положении**.
6. Откройте Монитор порта на скорости **9600 бод** для просмотра отладочных сообщений классификатора.

## Testing

Логика классификации вынесена в изолированный модуль без зависимости от платформы Arduino и компилируется стандартным компилятором C++ на любой ОС.

### Локальный запуск тестов:

#### Linux / macOS / MinGW:
```bash
cd firmware/direction_logic
g++ test_direction_logic.cpp direction_logic.cpp -o test_runner
./test_runner
```

#### Windows (MSVC Developer Command Prompt):
```cmd
cd firmware\direction_logic
cl /EHsc /std:c++17 test_direction_logic.cpp direction_logic.cpp /Fe:test_runner.exe
test_runner.exe
```

### Набор тестовых сценариев:
- **Нейтральный угол (0°):** всегда выдает `Direction::CENTER` при любом времени.
- **Шум шага (<250 мс):** кратковременный всплеск крена >25° продолжительностью <250 мс игнорируется и оставляет состояние `CENTER`.
- **Устойчивый наклон (>25°, >250 мс):** корректно активирует поворот `RIGHT`.
- **Гистерезис (25° / 17°):** возврат из `RIGHT` в `CENTER` происходит только при падении угла строго ниже $17^\circ$ ($25^\circ - 8^\circ$). Удержание угла 18°–24° сохраняет состояние поворота.
- **Симметричный поворот (LEFT):** проверка левого плеча и гистерезиса при отрицательных углах крена.

Детальное описание соответствия двоичных кодов и состояний приведено в документе [docs/truth_table.md](docs/truth_table.md).
