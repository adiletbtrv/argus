## Как это устроено

1. **Автономность трости от телефона.**  
   Все основные функции работают прямо на плате Arduino: опрос гироскопа, переключение светодиодов, замер дистанции сонаром и виброотклик. Если телефон сядет или приложение зависнет, трость продолжит полноценно работать сама по себе.
2. **Фильтрация шагов (гистерезис + задержка).**  
   При обычной ходьбе человек качает трость из стороны в сторону. Чтобы светодиоды не мигали на каждый взмах, мы сделали программный фильтр: порог наклона 25°, минимальное удержание 250 мс, а возврат назад в центр - только при угле меньше 17° (гистерезис 8°).
3. **Аппаратная защита светодиодов (74HC138).**  
   Сигналы поворота подключены через дешифратор 74HC138. Микросхема физически не может включить два выхода одновременно: горит либо левый, либо правый, либо оба выключены.
4. **Вибрация на ручке и телеметрия.**  
   Ультразвуковой датчик RCWL-9610A (HC-SR04) с таймаутом `pulseIn` 12000 мкс (около 2 м; `-1` при свободном пути и защита от ложного `0` при касании `< 1 см`) измеряет расстояние перед человеком. Если до препятствия не более 50 см, Arduino включает 5V модуль вибромотора в ручке (либо дискретный ключ на `SS8050 + 1N4007`) с неблокирующей динамической пульсацией (интервал уменьшается по мере приближения: `map(distance, 5, 50, 40, 400)` через автомат состояний на `millis()`). Дополнительно реализованы автокалибровка MPU6050 при старте (усреднение 20 отсчетов крена), защита шины I2C (`Wire.setWireTimeout(3000, true)`) и симметричный гистерезис детектора зарядки на `A1` (3 замера с шагом 20 мс от платы `18650 Battery Shield V3`). Каждые 180 мс трость отправляет по Bluetooth строку с дистанцией и направлением.

## Текущий статус

- **Железо и симуляции:**
  - Базовые схемы P0000-P0003 смоделированы в Tinkercad и проверены.
  - Линейка Wokwi-прототипов расширена до полной сквозной цепочки P0004-P0007:
    - **P0004:** Дешифратор 74HC138 + светодиоды поворотников (Active LOW, аппаратная взаимоблокировка).
    - **P0005:** Эмуляция угла крена + алгоритм гистерезиса (пороги 25°/17°, задержка 250 мс).
    - **P0006:** Согласующий делитель 5В→3.3В + односторонняя Bluetooth-телеметрия HC-05.
    - **P0007:** Финальный комплексный интерактивный стенд Argus Cane (сонар, зуммер, крен, 3x LED, кнопка).
  - Подготовлены подробные промпты автономного воспроизведения стендов (`PROMPTS_FOR_PROTOTYPES.md`).
- **Прошивка (Firmware):**
  - Алгоритм классификации поворотов с гистерезисом написан на чистом C++ и покрыт юнит-тестами (5 из 5 пройдены).
  - Основная прошивка трости (`argus_cane.ino`) объединяет автокалибровку и опрос MPU6050 (`Wire.setWireTimeout`), опрос сонара (таймаут 12000 мкс), управление 74HC138, динамический ШИМ-вибромотор на `millis()`, защиту от дребезга зарядки на `A1` и отправку телеметрии по Bluetooth.
- **Мобильное приложение (Android):**
  - Реализован контур компьютерного зрения на CameraX, MediaPipe Tasks (EfficientDet-Lite0, 10 целевых классов COCO) и ML Kit Image Labeling.
  - Подключен односторонний клиент Bluetooth SPP (`HC-05`/`HC-06`/`ARGUS`), Sensor Fusion и русская голосовая озвучка (`ru-RU`) с 5-уровневой иерархией приоритетов и локальным демо-режимом.
  - Подробная документация приложения доступна в [**`android/README.md`**](android/README.md).

## Архитектура

Система состоит из трех аппаратных узлов на трости и мобильного приложения:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      МОБИЛЬНЫЙ КОНТУР (Android App)                    │
│   Прием телеметрии (SPP) ──► Отображение статуса, навигация, голос     │
└───────────────────────────────────▲────────────────────────────────────┘
                                    │ Bluetooth (SPP) -> ТОЛЬКО ИСХОДЯЩИЙ ПОТОК
                                    │ Telemetry: "DIST:<см>,DIR:<DIR>\n"
┌───────────────────────────────────┴────────────────────────────────────┐
│                        АППАРАТНАЯ ЧАСТЬ ТРОСТИ                         │
│                                                                        │
│  [1. ПОДСИСТЕМА НАПРАВЛЕНИЯ]                                           │
│  MPU6050 (IMU) ──I2C──► Arduino Nano ──D2..D4──► 74HC138 ──► Светодиоды│
│                                                                        │
│  [2. ПОДСИСТЕМА ДИСТАНЦИИ И ТАКТИЛЬНОГО ОТКЛИКА] (Прототип P0002)      │
│  RCWL-9610A ──D5/D6──► Arduino Nano ──D9 (PWM)──► Модуль / SS8050      │
│                                                                        │
│  [3. ПОДСИСТЕМА ТЕЛЕМЕТРИИ]                                            │
│  Arduino Nano (D11 TX) ──[1k/2k]──► HC-05 (BT RXD)                     │
│                                                                        │
│  [ПИТАНИЕ]: 18650 Li-Ion (3.7V) ──► 18650 Battery Shield V3 ──► +5V    │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Определение направления:** датчик MPU6050 считывает крен трости, контроллер фильтрует шум шагов и передает двоичный код на входы 74HC138, который зажигает нужный поворотник.
2. **Дистанция и виброотклик:** ультразвуковой датчик RCWL-9610A (HC-SR04) сканирует пространство впереди (таймаут 12000 мкс). Если до преграды не более 50 см, контроллер через ШИМ на D9 запускает неблокирующую динамическую вибрацию.
3. **Исходящая телеметрия:** каждые 180 мс Arduino отправляет пакет `DIST:<см>,DIR:<CENTER|LEFT|RIGHT>\n` в модуль HC-05 (TX на D11) для смартфона.

## Связь по Bluetooth

Канал Bluetooth сделан строго односторонним (трость -> телефон):

- **Только передача:** трость передает наружу данные о дистанции и угле поворота.
- **Никаких команд снаружи:** трость ничего не слушает из радиоканала. В коде на входе RX сразу вызывается `stopListening()`, чтобы случайные помехи или пакеты не сбивали тайминги датчиков.
- **Безопасность:** если телефон разрядится, выключится или потеряет связь, светодиоды и вибрация на самой трости продолжат работать без пауз.

## Сборка и прошивка

### Нужные библиотеки Arduino:
- `Wire` (стандартная библиотека)
- `SoftwareSerial` (стандартная библиотека)
- `MPU6050_light` (ставится через Library Manager в Arduino IDE)

### Загрузка скетча:
1. Подключите Arduino Nano к компьютеру по USB.
2. Откройте файл `firmware/argus_cane/argus_cane.ino` в Arduino IDE.
3. Выберите плату **Arduino Nano**, процессор **ATmega328P** (или *Old Bootloader*) и соответствующий COM-порт.
4. Нажмите кнопку "Загрузить".
5. При включении держите трость вертикально и неподвижно 2-3 секунды, пока усредняются стартовые показания MPU6050.

## Тестирование

Классификатор наклонов написан на чистом C++ без привязки к железу Arduino, поэтому его можно запускать на компьютере:

### Сборка и запуск:

**GCC / Clang:**
```bash
cd firmware/direction_logic
g++ -std=c++11 test_direction_logic.cpp direction_logic.cpp -o test_runner
./test_runner
```

**MSVC:**
```cmd
cd firmware\direction_logic
cl /EHsc /std:c++17 test_direction_logic.cpp direction_logic.cpp /Fe:test_runner.exe
test_runner.exe
```

Что проверяют тесты:
- Нейтральный угол (0°) -> CENTER;
- Короткие покачивания при шаге (< 250 мс) -> фильтруются и не вызывают переключения;
- Устойчивый наклон (> 25°, удержание > 250 мс) -> переход в RIGHT / LEFT;
- Зона гистерезиса -> возврат в CENTER только при наклоне меньше 17°.
