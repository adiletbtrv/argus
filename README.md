## Как это устроено

1. **Автономность трости от телефона.**  
   Все базовые функции безопасности выполняются непосредственно на плате Arduino Nano: опрос гироскопа, переключение поворотников, замер дистанции сонаром и управление вибромотором в ручке. Если смартфон разрядится или потеряет связь, трость продолжает штатную работу без ограничений.
2. **Фильтрация шагов (гистерезис + удержание).**  
   При ходьбе пользователь раскачивает трость из стороны в сторону. Программный фильтр в модуле `direction_logic` отсекает взмахи шага: вход в поворот требует наклона `>= 25°` дольше `250 мс`, а возврат в центр происходит только при угле `< 17°` (гистерезис `8°`).
3. **Аппаратная защита светодиодов (74HC138).**  
   Указатели поворота подключены через КМОП-дешифратор `74HC138` (`Active LOW`, резисторы `470 Ом`). Микросхема физически удерживает активным только один канал: горит либо левый, либо правый сигнал, либо оба погашены.
4. **Локальная вибрация на ручке и исходящая телеметрия.**  
   Ультразвуковой датчик `RCWL-9610A` (`HC-SR04`) с таймаутом `pulseIn` `12000 мкс` (около `2 м`; `-1` на свободном пути и защита от ложного `0` при касании `< 1 см`) измеряет дистанцию впереди. При препятствии `<= 50 см` контроллер запускает 5V модуль вибромотора (либо дискретный ключ `SS8050 + 1N4007`) с неблокирующей динамической пульсацией `map(constrain(dist, 5, 50), 5, 50, 40, 400)` на `millis()`. Реализованы стартовая автокалибровка `MPU6050` (20 отсчетов), таймаут шины I2C `Wire.setWireTimeout(3000, true)` и симметричный гистерезис детектора зарядки `A1` (`3` замера по `20 мс` от платы `18650 Battery Shield V3`). Каждые `180 мс` трость отправляет по Bluetooth строку телеметрии.
5. **Мобильный контур компьютерного зрения и Sensor Fusion.**  
   Смартфон локально (`640x480`, защита от очереди кадров `isProcessing`) распознает 23 курированных навигационных класса препятствий COCO (`MediaPipe EfficientDet-Lite0` + `ObstacleCatalog` с градацией риска `dangerPriority` `1..3` + `TemporalObjectTracker`) и элементы инфраструктуры (`ML Kit`: лестницы с мебельной защитой от ложных срабатываний, стены, дверные проемы), объединяет их с телеметрией трости по 5-уровневой шкале приоритетов, озвучивает подсказки на русском языке (`SpeechCooldownPolicy`), поддерживает TalkBack и дублирует срочные угрозы двойной вибрацией смартфона.

## Архитектура

Система состоит из автономной аппаратной части на трости и мобильного приложения-ассистента:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                      МОБИЛЬНЫЙ КОНТУР (Android App)                    │
│   Прием SPP + Камера (COCO/ML Kit) ──► Sensor Fusion, TTS ru-RU, вибро │
└───────────────────────────────────▲────────────────────────────────────┘
                                    │ Bluetooth (SPP) -> ТОЛЬКО ИСХОДЯЩИЙ ПОТОК
                                    │ Telemetry: "DIST:<см>,DIR:<DIR>\n"
┌───────────────────────────────────┴────────────────────────────────────┐
│                        АППАРАТНАЯ ЧАСТЬ ТРОСТИ                         │
│                                                                        │
│  [1. ПОДСИСТЕМА НАПРАВЛЕНИЯ]                                           │
│  MPU6050 (IMU) ──I2C──► Arduino Nano ──D2..D4──► 74HC138 ──► Светодиоды│
│                                                                        │
│  [2. ПОДСИСТЕМА ДИСТАНЦИИ И ТАКТИЛЬНОГО ОТКЛИКА] (Прототип P0002)      │
│  RCWL-9610A ──D5/D6──► Arduino Nano ──D9 (PWM)──► Модуль / SS8050      │
│                                                                        │
│  [3. ПОДСИСТЕМА ТЕЛЕМЕТРИИ]                                            │
│  Arduino Nano (D11 TX) ──[1k/2k]──► HC-05 (BT RXD)                     │
│                                                                        │
│  [ПИТАНИЕ]: 18650 Li-Ion (3.7V) ──► 18650 Battery Shield V3 ──► +5V    │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Определение направления:** датчик `MPU6050` считывает крен трости, `DirectionClassifier` отфильтровывает качание шага и выставляет адрес на входах `74HC138`, зажигающем левый или правый поворотник.
2. **Дистанция и виброотклик:** ультразвуковой датчик `RCWL-9610A` сканирует путь впереди (таймаут `12000 мкс`). При препятствии `<= 50 см` ШИМ на `D9` формирует неблокирующую пульсацию вибромотора с учащением по мере сближения.
3. **Исходящая телеметрия и Sensor Fusion:** каждые `180 мс` Arduino отправляет пакет `DIST:<см>,DIR:<CENTER|LEFT|RIGHT>\n` в `HC-05` (`D11`), а смартфон объединяет его с видеопотоком для упреждающих голосовых и тактильных оповещений.

## Связь по Bluetooth

Канал Bluetooth спроектирован строго односторонним (**трость -> телефон**):

- **Только исходящая телеметрия:** трость транслирует пакеты `DIST:<см>,DIR:<CENTER|LEFT|RIGHT>\n` и не принимает входящих команд.
- **Аппаратно-программная изоляция RX:** вывод `TXD` модуля `HC-05` не подключен, а в `setup()` вызывается `btSerial.stopListening()`, отключающий прерывания приема.
- **Автоматический контроль контракта:** скрипт [`scripts/check_repo_standards.py`](scripts/check_repo_standards.py) на каждом PR блокирует появление любых обращений к `outputStream`, `.write(` и `.send(` в Android-коде и проверяет сохранность `btSerial.stopListening();` в прошивке.

## Сборка и прошивка

### Библиотеки Arduino
- `Wire` и `SoftwareSerial` (входят в стандартный пакет Arduino AVR Boards);
- `MPU6050_light` (устанавливается через Library Manager в Arduino IDE).

### Загрузка скетча на трость
1. Соберите электрические соединения согласно [`docs/pinout.md`](docs/pinout.md) (перед пайкой линии `A1` к `18650 Battery Shield V3` убедитесь мультиметром, что уровень не превышает `5.0 В`).
2. Подключите Arduino Nano к компьютеру по USB (аппаратный UART `D0/D1` свободен, отключать `HC-05` от `D11` не требуется).
3. Откройте [`firmware/argus_cane/argus_cane.ino`](firmware/argus_cane/argus_cane.ino), выберите плату **Arduino Nano**, процессор **ATmega328P** (или *Old Bootloader*) и нажмите **Upload**.
4. При каждом включении питания удерживайте трость вертикально и неподвижно `2-3 с` для завершения стартовой автокалибровки нуля `MPU6050`.

## Инструкция быстрого запуска для жюри (демонстрация)

Комплекс поддерживает два независимых сценария демонстрации на защите.

### Сценарий А - Jury Demo Mode (только смартфон, без аппаратной трости)
1. Установите `app-debug.apk` (из артефакта `app-debug` последнего прогона GitHub Actions или локальной сборки `cd android && ./gradlew assembleDebug`) на смартфон с Android 8.0+.
2. Запустите приложение **Argus** и выдайте разрешения на камеру и Bluetooth. Прозвучит фраза `"Камера активирована. Сканирование окружения запущено."`, экран останется активным (`FLAG_KEEP_SCREEN_ON`).
3. Нажмите кнопку **`"ТЕСТ / КАЛИБРОВКА"`**: при отсутствии трости поблизости плашка связи переключится в **`"БЛЮТУЗ: ДЕМО"`** и отработает встроенный сценарий телеметрии:
   - `CENTER, 60 см` -> зеленая карточка `"60 СМ"`, курс `"ПРЯМО"`;
   - через `1.2 с`: `LEFT, 28 см` -> красная карточка `"28 СМ"`, срочное голосовое предупреждение `"Внимание, близко препятствие: 28 см!"` и двойной виброимпульс смартфона;
   - через `1.5 с`: `RIGHT, 45 см` -> оранжевая карточка `"45 СМ"`, курс `"ВПРАВО"`.
4. Наведите камеру на стул, человека, глухую стену или дверной проем, чтобы проверить цветовые рамки зон (`LEFT`/`CENTER`/`RIGHT`), плашки угроз и голосовые подсказки обхода.

### Сценарий Б - Полный стенд (трость Argus + смартфон)
1. Включите тумблер питания трости от **`18650 Battery Shield V3`** и продержите трость вертикально `2-3 с` до окончания калибровки `MPU6050`.
2. В системных настройках Bluetooth смартфона выполните сопряжение с `HC-05` (PIN `1234` или `0000`), затем откройте приложение **Argus** (или нажмите `"ТЕСТ / КАЛИБРОВКА"`): статус сменится на **`"БЛЮТУЗ: ПОДКЛЮЧЕНО"`**.
3. **Проверка поворотников:** наклоните трость влево или вправо на угол `>= 25°` и удерживайте дольше `250 мс` - через дешифратор `74HC138` загорится соответствующий светодиод, а карточка `"КУРС"` покажет `"ВЛЕВО"` / `"ВПРАВО"` (возврат в `"ПРЯМО"` при угле `< 17°`).
4. **Проверка сонара и Sensor Fusion:**
   - на свободном пространстве (`> 200 см`) карточка дистанции горит зеленым со значением `"> 200 СМ"`;
   - при поднесении преграды ближе `50 см` в ручке трости включается динамическая вибрация с учащением ритма по мере сближения;
   - при дистанции `< 35 см` смартфон мгновенно озвучивает критическое расстояние и подает двойной вибросигнал;
   - при одновременном наклоне трости в сторону бокового объекта в кадре срабатывает упреждающий приоритет Sensor Fusion (`"Осторожно, слева преграда!"` / `"Осторожно, справа преграда!"`).
5. **Проверка детектора зарядки:** подключите кабель USB к `18650 Battery Shield V3` - после фильтрации на входе `A1` (`3` замера по `20 мс`) трость выдаст подтверждающий двойной виброимпульс.

## Сводная таблица проверок и CI

Все проверки запускаются автоматически в GitHub Actions ([`.github/workflows/android-ci.yml`](.github/workflows/android-ci.yml) и [`.github/workflows/pr-metadata.yml`](.github/workflows/pr-metadata.yml)) и воспроизводятся локально:

| Контур проверки | CI Job / Механизм | Объем и критерий прохождения | Команда локального запуска |
|:---|:---|:---|:---|
| **Android Unit + androidTest + APK** | `build-and-test` | **94/94** JVM-тестов (12 наборов), компиляция `androidTest`, сборка `app-debug.apk` | `cd android && ./gradlew testDebugUnitTest compileDebugAndroidTestKotlin assembleDebug` |
| **Firmware C++ Direction Logic** | `firmware-tests` | **5/5** модульных C++ тестов без единого предупреждения (`-Wall -Wextra -Werror`) | `g++ -std=c++17 -Wall -Wextra -Werror firmware/direction_logic/test_direction_logic.cpp firmware/direction_logic/direction_logic.cpp -o test_runner && ./test_runner` |
| **Стандарты и контракты репозитория** | `repo-standards` | **16/16** `unittest` + аудит всех файлов: UTF-8, типографика, односторонний Bluetooth, чистота `domain/` | `python3 -m unittest discover -s scripts -p "test_*.py" -v && python3 scripts/check_repo_standards.py` |
| **Метаданные и ревью Pull Request** | `pr-metadata` + `CODEOWNERS` | Авторазметка лейблов (`app`, `firmware`, `hardware`, `docs`), автора, вехи `"Финал"` и ревьюеров по путям | Срабатывает автоматически на событиях `pull_request` (`opened`, `synchronize`, `reopened`) |
