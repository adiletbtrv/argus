# Промпты для автономной генерации прототипов Wokwi (оптимизировано под Gemini 3.8 Flash High)

Данный документ содержит инженерные, сверхточные промпты для языковых моделей (включая легковесные и быстрые модели класса **Gemini 3.8 Flash High**).

Специфика небольших/быстрых моделей заключается в склонности к:
1. Выдумыванию произвольных пинов микроконтроллера при слабом контексте;
2. Ошибкам в инверсной логике (Active LOW vs Active HIGH);
3. Оставлению плейсхолдеров (`// TODO`, `// code here`);
4. Ошибкам в JSON-схемах `diagram.json` симулятора Wokwi.

Все приведенные ниже промпты составлены по принципу **Zero-Shot / Few-Shot Rigid Specification** с жестким контрактом входов и выходов, таблицами соединений и готовыми JSON-схемами.

## 0. Базовый системный промпт (Вставлять перед любой задачей)

```text
Ты — ведущий инженер по встроенным системам и схемотехнике проекта умной трости для незрячих "Argus".
Твоя задача — создать полностью рабочий, автономный прототип в симуляторе Wokwi для микроконтроллера Arduino Nano.

ЖЕСТКИЕ ПРАВИЛА И ОГРАНИЧЕНИЯ:
1. НИКАКИХ ПЛЕЙСХОЛДЕРОВ. Весь код на C++ и файлы конфигурации должны быть написаны от первой до последней строчки. Запрещены комментарии вида "// TODO", "// реализуйте здесь", "// код аналогичен".
2. СОБЛЮДЕНИЕ РАСПИНОВКИ ПРОЕКТА ARGUS. Ты обязан использовать ТОЛЬКО пины, зафиксированные в проектной документации (argus/docs/pinout.md и truth_table.md):
   - D2: Адрес A (бит 0) дешифратора 74HC138
   - D3: Адрес B (бит 1) дешифратора 74HC138
   - D4: Адрес C (бит 2, зафиксирован в LOW для Y0..Y3)
   - D5: Trig ультразвукового датчика HC-SR04
   - D6: Echo ультразвукового датчика HC-SR04
   - D8: LED влево (LEFT)
   - D9: LED прямо (CENTER) / ШИМ вибромотора
   - D10: LED вправо (RIGHT) / SoftwareSerial RX (NC, stopListening)
   - D11: SoftwareSerial TX (телеметрия на HC-05 через делитель 1к/2к)
   - A0: Потенциометр (эмуляция крена -45°..+45°)
   - A4 (SDA), A5 (SCL): Шина I2C для MPU6050
3. СТИЛЬ ДОКУМЕНТАЦИИ: Каждый прототип размещается в отдельном каталоге и содержит:
   - main.ino (основной скетч с подробными комментариями на русском языке)
   - diagram.json (валидная схема Wokwi с точными координатами, деталями и соединениями)
   - wokwi.toml (конфиг симулятора)
   - README.md (структурированное описание в стиле P0000–P0003: Название, Описание, Схема, Таблица пинов, Исходный код, Сценарий тестирования, Файлы).
```

## 1. Промпт для Прототипа P0004: Дешифратор 74HC138 + Поворотники (Active LOW)

```text
Задача: Создай в каталоге `argus/hardware/wokwi/P0004/` полноценный симуляционный прототип P0004 для проверки логики дешифратора 74HC138 и светодиодов поворотников.

Контекст и физика работы:
- В трости Argus переключение поворотников реализовано через 3-to-8 дешифратор 74HC138 (КМОП).
- Выходы дешифратора инверсные (Active LOW): активный выбранный выход притягивается к GND (LOW), неактивные остаются в HIGH (+5V).
- Светодиоды подключены по схеме с втекающим током (Current Sinking): +5V -> резистор 470 Ом -> Анод LED -> Катод LED -> выход /Y1 (левый) или /Y2 (правый).
- При коде CBA = 000 активен выход /Y0 (он не подключен, светодиоды выключены — нейтраль/прямо).
- При коде CBA = 001 активен выход /Y1 (загорается оранжевый LED LEFT).
- При коде CBA = 010 активен выход /Y2 (загорается желтый LED RIGHT).
- При коде CBA = 011 активен выход /Y3 (резерв, диоды выключены).
- Это обеспечивает физическую невозможность одновременного включения левого и правого сигналов (аппаратная взаимоблокировка).

Требуемые файлы:
1. `74hc138.chip.json` — описание пинов кастомного чипа для Wokwi:
{
  "name": "74hc138",
  "author": "Argus Hardware Team",
  "pins": [
    "A", "B", "C", "G2A", "G2B", "G1", "Y7", "GND",
    "Y6", "Y5", "Y4", "Y3", "Y2", "Y1", "Y0", "VCC"
  ]
}

2. `74hc138.chip.c` — логика работы чипа на C с использованием Wokwi Chip API (проверка стробов G1==HIGH, G2A==LOW, G2B==LOW, декодирование адреса A|B<<1|C<<2, установка выбранного выхода в LOW, остальных в HIGH).

3. `main.ino` — скетч Arduino Nano:
- Настройка пинов PIN_A=2, PIN_B=3, PIN_C=4 на OUTPUT;
- Инициализация Serial 9600;
- Циклический перебор состояний с интервалом 2000 мс:
  - STATE 0: CBA=000 -> нейтраль, вывод в Serial "[STATE 0] CBA=000 -> /Y0 Active (LOW) -> CENTER (LEDs OFF)";
  - STATE 1: CBA=001 -> лево, вывод "[STATE 1] CBA=001 -> /Y1 Active (LOW) -> LEFT TURN (LED LEFT ON)";
  - STATE 2: CBA=010 -> право, вывод "[STATE 2] CBA=010 -> /Y2 Active (LOW) -> RIGHT TURN (LED RIGHT ON)";
  - STATE 3: CBA=011 -> резерв, вывод "[STATE 3] CBA=011 -> /Y3 Active (LOW) -> RESERVE".

4. `diagram.json` — схема соединений в Wokwi:
- Arduino Nano, chip:74hc138, 2x wokwi-resistor (470 Ом), 2x wokwi-led (orange для Y1, yellow для Y2);
- Соединения: Nano 5V к chip VCC, G1, r_left:1, r_right:1; Nano GND к chip GND, G2A, G2B;
- Nano D2 к chip:A, D3 к chip:B, D4 к chip:C;
- r_left:2 к led_left:A, led_left:C к chip:Y1;
- r_right:2 к led_right:A, led_right:C к chip:Y2.

5. `wokwi.toml` — файл с версией 1.
6. `README.md` — файл документации по ГОСТу проекта Argus (описание, схема ASCII, таблица истинности, код, инструкция по запуску).
```

## 2. Промпт для Прототипа P0005: Эмуляция крена + Алгоритм гистерезиса

```text
Задача: Создай в каталоге `argus/hardware/wokwi/P0005/` автономный симуляционный прототип P0005 для проверки алгоритма классификации направления трости с двухпороговым гистерезисом и фильтром дребезга шагов.

Контекст и математическая модель:
- Трость считывает крен (roll) датчиком MPU6050. В симуляторе крен эмулируется потенциометром на аналоговом входе A0.
- Формула пересчета: roll = ((float)analogRead(A0) / 1023.0f) * 90.0f - 45.0f; (диапазон от -45° до +45°).
- Порог срабатывания: при |roll| >= 25.0° и удержании свыше 250 мс трость фиксирует поворот (LEFT при roll <= -25°, RIGHT при roll >= +25°).
- Защита от колебаний шага: кратковременные наклоны длительностью < 250 мс игнорируются, состояние остается CENTER.
- Гистерезис: возврат из состояния поворота в CENTER происходит только тогда, когда угол уменьшается ниже 17.0° (порог 25° минус гистерезис 8°).
- Индикация: 3 светодиода:
  - D8: Зеленый LED (LEFT);
  - D9: Желтый LED (CENTER);
  - D10: Синий LED (RIGHT);
  Каждый светодиод подключен анодом к пину Nano, катодом через резистор 220 Ом к GND.

Требуемые файлы:
1. `direction_logic.h` и `direction_logic.cpp` — оригинальные модули классификатора направления с классом DirectionClassifier, enum class Direction { CENTER, LEFT, RIGHT } и методом classify(float rollDeg, unsigned long currentMs).
2. `main.ino`:
- Чтение A0, вычисление roll;
- Вызов classifier.classify(roll, millis());
- Управление светодиодами D8, D9, D10;
- Вывод в Serial (115200 бод) телеметрии в формате: "TILT:<roll>,DIR:<CENTER|LEFT|RIGHT>".
3. `diagram.json`:
- wokwi-arduino-nano, wokwi-potentiometer (SIG на A0, VCC на 5V, GND на GND), 3x wokwi-led (зеленый, желтый, синий), 3x wokwi-resistor (220 Ом).
4. `wokwi.toml` с version = 1.
5. `README.md` с подробным описанием логики гистерезиса, обоснованием порогов 25°/17° и 250 мс, таблицей пинов и сценарием тестирования в Wokwi Serial Plotter.
```

## 3. Промпт для Прототипа P0006: Делитель 5В→3.3В + Односторонняя телеметрия HC-05

```text
Задача: Создай в каталоге `argus/hardware/wokwi/P0006/` аппаратный прототип P0006 для проверки согласования уровней UART и одностороннего протокола Bluetooth-телеметрии трости Argus.

Контекст и схемотехника:
- Микроконтроллер Arduino Nano работает с логическими уровнями 5V TTL.
- Модуль Bluetooth HC-05 имеет вход RXD с толерантностью только до 3.3V LVTTL. Подача 5V напрямую выведет модуль из строя.
- Для согласования применяется резистивный делитель:
  Nano D11 (TX 5V) -> резистор R1 (1 кОм) -> Средняя точка -> RXD HC-05 (3.3V)
  Средняя точка -> резистор R2 (2 кОм) -> GND
  Расчетное напряжение: V_out = 5.0V * (2000 / (1000 + 2000)) = 3.33V.
- Безопасность и односторонний режим:
  - Линия TXD HC-05 не подключается;
  - Пин D10 формально объявляется в SoftwareSerial(10, 11), но в setup() сразу вызывается btSerial.stopListening();
  - Входящие радиопомехи или команды снаружи не могут прервать ультразвуковой замер дистанции (pulseIn).
- Формат исходящего пакета телеметрии:
  "DIST:<см>,DIR:<CENTER|LEFT|RIGHT>\n"

Требуемые файлы:
1. `main.ino`:
- Инициализация аппаратного Serial (9600) для USB-отладки;
- Инициализация SoftwareSerial btSerial(10, 11) на 9600 бод с немедленным вызовом stopListening();
- Каждую секунду генерация тестового пакета телеметрии и отправка в btSerial;
- Логирование в Serial Monitor с пояснением безопасного напряжения 3.33V на выходе делителя.
2. `diagram.json`:
- Nano, wokwi-resistor 1k, wokwi-resistor 2k, светодиод-индикатор импульсов данных на средней точке (через 470 Ом на GND).
3. `wokwi.toml` с version = 1.
4. `README.md` с электротехническим расчетом делителя, формулами токов, описанием протокола и чеклистом безопасности.
```
